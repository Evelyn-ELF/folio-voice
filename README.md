# Folio Voice

本地电子书转音频与同步有声书系统。支持EPUB及文字、扫描、混合PDF输入、多声音管理，输出可直接收听的音频与可重排同步EPUB。采用Docker应用＋Mac原生MLX服务。

当前处于设计阶段，产品实现、真实音频质量和设备兼容性尚待验证。日常交付目标是系统自动完成质量检查，用户无需全量听审。

## 唯一开发入口

日常开发只使用以下四份文档。初次了解项目，先读系统设计第1–4章；开始具体工作，先看开发任务的当前优先事项，再按任务链接查阅设计、工程规范和验证计划。术语与编号统一见[系统设计说明](docs/系统设计.md#terms)，无需逐次通读全部内容。

| 文档 | 唯一职责 | 何时查看 |
|---|---|---|
| [系统设计](docs/系统设计.md) | 产品需求、架构、数据、接口、Agent、质量门槛和用户行为 | 判断要实现什么、行为边界及设计变更 |
| [工程规范](docs/工程规范.md) | 权威依据、文档/编码/测试/交付方法及适用边界 | 确定如何开展工程工作、核查规范来源 |
| [验证计划](docs/验证计划.md) | V01–V21需求验证、E01–E08实验、C01–C12契约用例和设备矩阵 | 实施前确定验证方法，实施后提交证据 |
| [开发任务](docs/开发任务.md) | F01–F12工作状态、依赖、资源、完成条件及下一步 | 开始工作、状态变化和阶段结束 |

[AGENTS.md](AGENTS.md)是仓库操作约定，不另行定义产品行为。

## 一致性与变更规则

用户明确要求决定需求；落实时同步修改上述文档，不能只留在聊天记录中。系统设计是产品规则的唯一来源，工程规范规定工作方法，验证计划规定证明方法，开发任务只记录执行状态。后两者不得隐式改变产品范围或降低质量门槛。

文档之间、文档与机器契约之间出现冲突时，视为待修复缺陷：登记到相关开发任务，明确影响范围并同步修正依据和验证项后再实现受影响部分；不按文件日期、篇幅或个人偏好自行选择。无关工作可继续。

`docs/contracts/`中的Schema和样例是系统设计的机器可读附件；`docs/validation/`只保存实际校验结果及环境，不是额外开发规范。各项完成状态统一在开发任务维护，不因存在报告或文档而认定产品通过。

每次开发变更按[文档维护流程](docs/工程规范.md#document-maintenance)同步相关内容，并运行`python3 tools/check_documents.py`；代码、契约、测试与文档按[变更完成条件](docs/工程规范.md#change-completion)共同交付和评审。

## 归档边界

[archive/](archive/README.md)保存不参与当前开发的资料快照，仅供明确需要追溯时查阅。不列入日常阅读、默认搜索、校验或实现依据；其中的工作指令不适用于当前开发。新增规则优先修改四份活动文档，不再建立并行方案或第二套任务清单。

所有回答、文档与界面使用中文。私人书籍、参考声音、模型权重、凭据和实际成品不进入Git或公开镜像。
